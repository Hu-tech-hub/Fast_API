# 🔥 1. 라이브러리(Library) vs 프레임워크(Framework)

| 구분 | 라이브러리 | 프레임워크 |
|:---|:---|:---|
| **정의** | "내가 필요한 기능을 갖다 쓰는 도구" | "전체 프로그램의 뼈대를 주고, 거기에 맞춰 내가 코드를 짜는 틀" |
| **주도권(Control)** | **내가** 직접 필요할 때 호출(call)함 | **프레임워크가** 내 코드를 호출(call)함 (거꾸로 동작) |
| **예시** | NumPy, Pandas, Matplotlib | Django, FastAPI, Spring |
| **비유** | 공구 상자: 망치, 드릴, 스패너 골라서 쓰는 것 | 집 짓기: 집 구조가 이미 있고 방 꾸미는 것만 하는 느낌 |

---

# 🏛️ 2. 좀 더 쉽게

- **라이브러리**:  
  > "필요할 때 가져다가 쓰는 도구 모음."

- **프레임워크**:  
  > "틀을 주고, 그 틀 안에서만 내가 일하는 것."

**차이 핵심**:  
> **주도권(Control)**이 누구한테 있느냐?  
> → 라이브러리는 **내가** 부르고,  
> → 프레임워크는 **프레임워크가** 나를 부른다.

---

# 🚀 3. FastAPI는 뭐냐?

✅ FastAPI는 **프레임워크**다.  
- 서버를 만들기 위한 전체 구조를 제공한다.
- 내가 코드를 작성하면 FastAPI가 알아서 호출하고 연결해준다.

예를 들어:
```python
@app.get("/")
def hello():
    return {"message": "hi"}
```
- 내가 `hello`라는 함수를 만들었지만,
- 이걸 호출하는 건 내가 아니라 **FastAPI**다.  
(브라우저에서 요청 오면 FastAPI가 내 함수를 자동으로 불러준다.)

**즉,** FastAPI는
> "웹 서버를 만들고, API를 쉽게 구성할 수 있도록 뼈대를 다 제공해주는 프레임워크"다!

# 🧠 다시 요약

| 질문 | 답변 |
|:---|:---|
| 라이브러리는 뭐야? | 내가 필요한 기능을 골라서 가져다 쓰는 도구 모음. |
| 프레임워크는 뭐야? | 프로그램의 큰 틀을 잡아주고, 그 안에서 내가 코딩하는 구조. 주도권은 프레임워크에 있음. |
| FastAPI는? | 웹 서버를 빠르고 쉽게 만들 수 있도록 틀을 제공하는 **프레임워크**다. |

# 📦 추가 참고 (간단 비교)

| 항목 | 라이브러리 | 프레임워크 |
|:---|:---|
| 사용법 | 함수나 클래스를 직접 호출 | 특정 규칙에 맞춰 코드를 작성 |
| 예시 | requests, numpy, pandas | FastAPI, Flask(거의 프레임워크), Django |
| 개발자 역할 | 필요한 부분만 가져다 씀 | 전체 구조에 맞춰 개발 |
