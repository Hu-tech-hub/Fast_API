## 1. **basic/main.py 코드는 동기(synchronous)**

```python
def read_root():
    return {"message": "Hello, FastAPI!"}
```

- `def`로 함수를 만들었지? (`async def`가 아니라 그냥 `def`)
- 이 말은 **요청이 들어오면**,  
  → 이 함수가 **끝날 때까지 기다렸다가** 결과를 보내준다는 뜻이야.
- 즉, **일을 하나 끝낼 때까지 다른 일은 안 하고 기다린다**는 거야.

**비유**하면:
> **편의점 알바생이 혼자** 일하는데, 손님이 오면 주문을 다 받고 계산을 다 끝내고 다음 손님을 받는 거랑 비슷해.

---

## 2. **비동기(asynchronous)로 바꾸면?**

```python
async def read_root():
    return {"message": "Hello, FastAPI!"}
```

- `def` 대신에 `**async def**` 이렇게 쓰면, 이 함수는 **비동기 함수**가 된다!
- 비동기 함수는,  
  → 요청을 처리하다가 시간이 오래 걸리는 작업(예를 들면 데이터베이스 요청, 파일 다운로드)이 있으면,  
  → **"잠깐 다른 일 하고 올게!"** 하고 멈추지 않고 다른 요청을 바로 처리할 수 있어.

**비유**하면:
> **편의점 알바생이 3명** 있는데, 계산 기다리는 동안 다른 손님도 동시에 받아주는 거야.  
> 계산을 처리하는 동안 다른 손님 커피도 담아주고, 택배도 받아주고 빠르게 왔다갔다 하는 것!

---

## 3. **왜 비동기를 쓸까?**

- FastAPI는 원래부터 **비동기 처리**에 엄청 강한 프레임워크야. (ASGI 서버 사용)
- 특히 **DB에서 데이터 가져오기**나 **외부 서버에 요청 보내기** 같은 **오래 걸리는 작업**이 많으면,  
  비동기로 짜야 서버가 빠르고 튼튼해져.

만약 다 동기로 짜면,
- 누가 하나 파일 업로드하는 동안
- 다른 사람이 서버에 접속하면
- **"기다려~"** 하고 다 막혀버린다.

---

## 4. **정리표**

| 구분 | 동기 (`def`) | 비동기 (`async def`) |
|:---|:---|:---|
| 처리방식 | 한 번에 하나만 처리 | 동시에 여러 작업 처리 가능 |
| 특징 | 느릴 수 있음 | 빠르고 효율적 |
| FastAPI 권장 방식 | 간단할 땐 OK | 복잡하거나 오래 걸리는 작업은 비동기 추천 |

## 5. **너 코드에서 비동기 버전으로 고치면?**

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
async def read_root():
    return {"message": "Hello, FastAPI!"}

@app.get("/items/{item_id}")
async def read_item(item_id: int, q: str = None):
    return {"item_id": item_id, "q": q}
```

→ 이렇게 `async def`로 고치기만 하면 된다. 🚀
