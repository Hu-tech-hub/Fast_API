## ✅ FastAPI 요청 파라미터 전달 방식 정리

FastAPI에서는 HTTP 요청을 처리할 때, 클라이언트로부터 다양한 방식으로 데이터를 전달받을 수 있다. 주요 전달 방식은 다음과 같다:

---

### 1. 🔷 **Path Parameter (경로 변수)**

- **URL 경로에 직접 포함되는 값**
- 주로 리소스를 고유하게 식별할 때 사용

#### 📌 예시
```python
@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"user_id": user_id}
```

#### 📌 요청 예시
```
GET /users/42
```

#### ✅ 특징
- 필수 값
- URL 경로의 일부로 사용되어야 함
- 타입 검사를 지원함 (`int`, `str`, 등)

---

### 2. 🔷 **Query Parameter (쿼리 문자열)**

- **URL 경로의 ? 이후 key=value 형식으로 전달되는 값**
- 선택적 인자에 적합
- 필터, 정렬, 페이징 등에 자주 사용

#### 📌 예시
```python
@app.get("/items")
def read_items(skip: int = 0, limit: int = 10):
    return {"skip": skip, "limit": limit}
```

#### 📌 요청 예시
```
GET /items?skip=10&limit=5
```

#### ✅ 특징
- 선택적(default 값을 가질 수 있음)
- URL에 드러나므로 민감 정보에는 부적합
- 단순한 키-값 형태가 적합

---

### 3. 🔷 **Request Body (요청 본문)**

- **POST, PUT, PATCH 요청 등에서 JSON 등의 형태로 전달되는 데이터**
- 복잡한 구조(딕셔너리, 리스트, 중첩 데이터 등) 전달 시 사용
- `pydantic` 모델로 구조화하여 자동 검증 가능

#### 📌 예시
```python
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    price: float

@app.post("/items")
def create_item(item: Item):
    return item
```

#### 📌 요청 예시
```json
POST /items
{
  "name": "Apple",
  "price": 3.5
}
```

#### ✅ 특징
- 주로 POST, PUT 요청에서 사용
- 복잡한 구조에 적합
- 요청 URL에는 보이지 않음

---

### 4. 🔷 **Header Parameter**

- 클라이언트가 HTTP 헤더에 담아 보내는 값
- 인증 토큰, 클라이언트 정보, 언어 설정 등에 사용

#### 📌 예시
```python
from fastapi import Header

@app.get("/info")
def read_info(user_agent: str = Header(default=None)):
    return {"User-Agent": user_agent}
```

---

### 5. 🔷 **Cookie Parameter**

- 클라이언트가 브라우저에 저장한 쿠키를 통해 전달하는 값
- 세션 정보, 사용자 식별 등에 사용

#### 📌 예시
```python
from fastapi import Cookie

@app.get("/welcome")
def welcome(session_id: str = Cookie(default=None)):
    return {"session_id": session_id}
```

---

## ✅ Query vs Body: 어떤 걸 써야 할까?

| 구분 | Query Parameter | Request Body |
|------|------------------|---------------|
| ✅ 사용 메서드 | 주로 GET | 주로 POST, PUT, PATCH |
| ✅ 데이터 노출 | URL에 노출됨 | 본문에 숨겨짐 |
| ✅ 구조 | 단순 키-값 (한 줄로 표현) | 복잡한 JSON, 리스트, 중첩 구조 |
| ✅ 보안 | 민감 정보에는 부적합 | 상대적으로 안전 |
| ✅ 캐싱 | URL 기반 캐시 가능 | 캐싱 어렵다 |
| ✅ 사용 목적 | 필터링, 검색 옵션 등 | 새 리소스 생성, 전체 정보 전달 등 |

### 🔔 정리
- **간단한 값, 검색/필터링용 → Query Parameter**
- **복잡한 데이터, 생성/수정용 → Request Body**

---

필요하면 `Header`, `Cookie`까지 받을 수 있으며, FastAPI는 이 모든 파라미터 타입에 대해 자동으로 **유효성 검사**, **문서화(Swagger)** 를 지원한다.
