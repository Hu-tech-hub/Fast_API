## ✅ Pydantic 클래스와 일반 클래스의 차이

| 항목 | Pydantic 클래스 (`BaseModel`) | 일반 클래스 (`class`) |
|------|-------------------------------|------------------------|
| **용도** | 데이터 모델 정의, 유효성 검사, 직렬화 | 로직 중심의 객체 생성 |
| **자동 검증** | ✅ 타입 자동 검사 및 예외 발생 (`ValidationError`) | ❌ 타입 검증 수동 구현 필요 |
| **입력 방식** | `dict`, `**kwargs`, JSON 문자열 파싱 가능 | 일반적으로 `__init__()` 호출만 가능 |
| **중첩(Nested) 지원** | ✅ 내부 필드도 다른 `BaseModel`로 자동 파싱됨 | ❌ 직접 중첩 클래스 생성 및 매핑 필요 |
| **직렬화 지원** | `.model_dump()` → `dict`<br>`.model_dump_json()` → JSON 문자열 | ❌ 수동으로 `__dict__`, `json.dumps()` 처리 |
| **문서화 지원 (FastAPI)** | ✅ 자동 문서화 (`/docs`, `/openapi.json`) | ❌ 지원 안 됨 |
| **기본값 및 설명 설정** | `Field(...)`를 통해 기본값, 예시, 설명 작성 가능 | 수동으로 생성자 내부에서 처리 |
| **대표 사용처** | FastAPI API의 Request/Response Body<br>데이터 유효성 검사 및 구조화 | 비즈니스 로직, 상태 관리, UI 클래스 등 |

## 📌 예시 비교

### 🔷 Pydantic 모델: 중첩 JSON도 자동 파싱

```python
from pydantic import BaseModel

class Address(BaseModel):
    street: str
    city: str

class User(BaseModel):
    name: str
    age: int
    address: Address

json_data = {
    "name": "Alice",
    "age": 30,
    "address": {
        "street": "123 Main St",
        "city": "Seoul"
    }
}

user = User(**json_data)  # 자동으로 address도 Address 객체로 변환됨
print(user.address.city)  # 출력: Seoul
```

### 🔶 일반 클래스: 수동으로 매핑해야 함

```python
class Address:
    def __init__(self, street, city):
        self.street = street
        self.city = city

class User:
    def __init__(self, name, age, address: dict):
        # address가 dict이므로 수동으로 Address 객체로 변환해야 함
        self.name = name
        self.age = age
        self.address = Address(**address)

json_data = {
    "name": "Alice",
    "age": 30,
    "address": {
        "street": "123 Main St",
        "city": "Seoul"
    }
}

user = User(**json_data)
print(user.address.city)  # 출력: Seoul
```

## 🧠 요약

> Pydantic은 **데이터를 구조화하고 검증**하는 데 최적화된 도구입니다.  
> 일반 클래스는 **로직 중심의 객체나 상태 관리에 적합**합니다.

실무에서는 다음과 같은 방식으로 역할 분담을 합니다:

- **입출력용 데이터 모델 (API, DB)** → ✅ Pydantic 모델
- **내부 로직 처리 클래스 (기능, 메서드 등)** → ✅ 일반 클래스 또는 서비스 계층
